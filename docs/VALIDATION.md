### 해결한 개발 환경 문제

1. Windows 경로 `C#`의 `#` 문자를 Vite가 URL fragment로 해석해 모듈을 찾지 못함. 동일 소스를 임시 경로에 복사하고 Node와 Vite의 symlink 보존 옵션으로 실행하는 테스트 진입점을 추가함. 임시 경로 검증 후 정리하고 원본 폴더는 유지함.
2. Tailwind의 기본 CSS import를 해석할 때 특수문자 경로가 잘못 변환됨. import 해석이 필요 없는 Tailwind utilities/theme 지시문과 프로젝트 자체 CSS를 사용함.
3. API 배치 테스트가 하나의 Response 객체를 재사용해 두 번째 JSON 읽기에 실패함. 요청마다 새 Response를 만드는 모킹으로 수정함.

## 자동 검증 범위

- API: Client 헤더, 커서 인코딩, KST 파싱, 401/403/404/429/500, 제한 재시도, 응답 필드 손실, 채널 20개 배치와 누락 감지
- 동기화: 전체 순회, 중복 제거, 부분 실패 스냅샷 보존, 커서 반복, 페이지 한도, 빈 결과, 실행 중복, 쿨다운, 비밀값 오류 마스킹
- 조회: 상태 집계, 온라인 우선, 검색·필터·페이지, 즐겨찾기 빈 목록, 지연 기준, URL 검증
- DB: 실제 마이그레이션 적용, 온라인/오프라인 전환, 숨김 유지, 롤백, 종료 이력 보존 (PGlite PostgreSQL 엔진)
- E2E: 데스크톱/360px 모바일, 필터·검색·초기화, 저장 지속, 오프라인 비활성화, 성인 썸네일 블러, 샘플 안내, 실제 링크 popup(네트워크 모킹), 지연 안내, 쿼리·인증 검증

## 2026-09-14~15 실제 데이터 연결 검증

- 치지직 Developers에 LiveScope 등록, Client 인증으로 공식 라이브 API HTTP 200 확인. 인증값은 Git에서 제외한 `.env.local`에만 저장.
- PostgreSQL 17.11을 프로젝트 내부에 구성하고 `127.0.0.1:55432`에서 실행. 앱 전용 계정은 슈퍼유저가 아님을 확인.
- 실제 PostgreSQL의 독립된 두 세션에서 같은 advisory lock을 동시에 획득할 수 없음을 확인.
- 첫 전체 수집: **260페이지, 실제 라이브 5,169개, 30.331초**, COMPLETE 및 트랜잭션 저장 성공.
